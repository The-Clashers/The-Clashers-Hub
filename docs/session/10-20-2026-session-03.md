## Decisions

- One gold accent, used sparingly (numbers, verdicts, focus). Light theme
  uses #B8860B (a darker gold that still clears 4.5:1 on white), dark theme
  brightens to #E0B84C so the accent still reads as gold against the
  near-black canvas. Gold is not a generic brand color and never appears on
  chrome.
- Canvas: white in light, near-black (#0B0B0A) in dark. Panels float on the
  canvas; both themes share the spacing, radius, typography, layout, and
  motion scales so only the color surface changes between them.
- Contrast pairs verified at token-add time. Lowest text-on-canvas pair:
  textMuted on canvas at 7.0:1 (light) and 8.2:1 (dark), both clear of the
  4.5:1 floor (NFR-06). textMuted on panel is the pair to re-check if either
  value moves.
- Theme control: localStorage under tch.theme (same storage surface the spec
  blesses for saved tags, CON-06), tracks prefers-color-scheme only while the
  user has not pinned a choice, mirrors to Appearance.setColorScheme for RN
  components that read it, and paints the document root so the body matches
  the canvas on overscroll.
- Base styles are a function of the theme (createBaseStyles(theme)) so the
  StyleSheet is bound to the active canvas without re-deriving chrome in
  every screen. Screens compose base.panel / base.title / etc. with their own
  StyleSheet.create; they do not pull raw tokens for chrome.
- System font stack as a comma-separated string so it passes RN's
  TextStyle.fontFamily (single string) without a cast and still gives the
  fallback chain the design language wants. Numbers use tabular-nums via the
  metric style in baseStyles.
- /tokens is a review surface, not a product route. It stays in the router so
  design QA can pull it up on the preview deploy without rebuilding.
- Breakpoints come from useWindowDimensions into breakpointFor; no CSS media
  queries scattered through components (07 §3, RN paradigm).
