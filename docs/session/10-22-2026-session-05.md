## Decisions

- Handlers are web-standard `Request -> Response` functions; `api/` files are two-line adapters so the platform runtime and the local dev server run the same code, and an adapter swap is the only change needed if the platform ever disagrees.
- Shared tier code lives in `server/` (upstream client, cache, contract, routes) instead of inside `api/`, keeping function files routable-only; `01-tech-stack` section 5 was updated to record the layout.
- Server-side 429 retries use quick fixed backoffs (500 ms, 1500 ms, three attempts, 4 s per-attempt timeout); a Retry-After header is surfaced to the client on the 503, never waited out server-side, so the tier always answers well inside the 20 s function ceiling set in `vercel.json`.
- The private warlog response carries an age field like every other 200; `04-api-strategy` section 6 was updated to match.
- A 403 on the warlog route maps to the private state only for reasons accessDenied and privateWarLog; anything else stays an upstream failure. Live probing showed the real API answers a private log with reason accessDenied (tag-dependent on the same endpoint at the same moment), so accepting it is what makes the designed notice actually appear.
- Vitest landed now (2.1.9, the Vite-5-compatible line) rather than with the CI card, because the tier's cache, retry, and mapping logic deserve table-driven tests from day one.
