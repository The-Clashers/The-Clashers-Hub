## Decisions

- The hello clan screen is a review surface like /tokens, not a feature. It lives at /hello so the M1 clan detail screen (F-04) can later take over /clan/:tag without a route conflict; the state matrix and the typed client carry over to M1 unchanged.
- #G88CYQP picked as the hardcoded tag for three properties: well-known (won't vanish), populated (members > 0 reads as a real number), and public war log (so a later warlog probe on the same tag is not a surprise). The tag is canonical so the tier's normalization is a no-op on it.
- The typed client lives in src/api/clan.ts, the layout the concept doc planned (01 section 5). It models only the fields the hello screen and the M1 clan detail screen read; a field the app does not read stays untyped on purpose so an upstream payload change never breaks the build, only the screen that needs the new field.
- The contract's three error outcomes (404 not_found, 503 upstream_busy, 502 upstream_unreachable) become a discriminated union (ClanQueryResult) so the screen branches on `result.kind` instead of re-checking strings. ClanFetchError carries the union so TanStack Query sees a single failure path with all the context.
- Loading state is a layout-matched skeleton, never a spinner (06 section 3). The skeleton mirrors the success layout: badge slot, name line, tag line, three chips, description block. A pulsing placeholder is the signal that data is on its way.
- The 404 retry is disabled: a 404 on a hardcoded tag means the clan was retired or the constant drifted, retrying burns no upstream calls (30 s negative cache) but cannot fix anything. The other errors get the single default retry and a manual retry button.
- The success state carries a "fetched Ns ago" chip that reads the `age` field the tier injects. It mirrors the manual-refresh concept (06 section 2) without shipping the actual refresh control yet (that is F-19, T-M2-7).
- Clan badge comes from the game API's iconUrls (07 section 7), rendered through RN Image in a fixed 56 px slot so a slow CDN load never reflows the layout. A badge placeholder covers the rare missing-URL case.
- HomeScreen now carries two review links side by side: /hello (primary, gold) and /tokens (secondary, panel chrome). The gold accent stays reserved for the live-data smoke, the one a reviewer is most likely to want first.
