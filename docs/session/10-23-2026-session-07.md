## Decisions

- The api adapters now export the documented web-standard shape: a default object with a fetch method, wrapping the shared handler. A bare `export default handler` is invoked Node-style (req, res) on the platform, so `new URL(request.url)` threw on the bare path and every route answered FUNCTION_INVOCATION_FAILED on Vercel while working locally (our dev-server speaks web-standard). The object form is load bearing, not style; each file says so in a comment so nobody flattens it back.
- The dev-server (scripts/dev-server.ts) now calls `defaultExport.fetch(request)`, so local dev exercises the exact entry point the platform invokes.
- lineHeight tokens stay as design ratios, but createBaseStyles converts each to pixels (ratio x fontSize) via a lineBox helper in one place. RN Web reads a numeric lineHeight as pixels, so `lineHeight: 1.2` compiled to `line-height: 1.2px` under a 36px display font: the line box collapsed and stacked sibling texts on top of each other (the reported "text overlaps" on the deployed home). Screens that already multiplied (TokenScreen, the hello screen description) were correct; only the base styles were not.
- vercel.json gains the SPA catch-all rewrite `/(.*) -> /index.html`. The Vercel docs confirm the filesystem (static files and api functions) takes precedence over rewrites, so /api/* keeps hitting the functions while client-side routes like /hello serve the shell on direct load and refresh.
- The hardcoded smoke tag is now our own clan #2JPCYP98L: it exists as long as the project does, it is populated (47 members), and its war log is public (verified live: the warlog route answers 200 against it).
