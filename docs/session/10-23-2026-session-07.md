## Decisions

- The platform's Node launcher invokes a function file's default export Node-style, as (req, res), regardless of the export's shape. The original bare web-standard handler crashed there (req.url is a bare path, so new URL threw Invalid URL), and the documented fetch-object form crashed too (the launcher calls the object itself, which is not a function). The api adapters now export a plain function produced by nodeHandler (server/vercel-adapter.ts), which builds a real Request from the Node req, runs the shared web-standard handler, and pipes the Response into the Node res. If a future launcher calls it web-style instead, the wrapper detects the Request and passes it through, so one file serves both contracts; the dev server already uses that web-style path.
- The routing manifest (inspected via a local vercel build) puts vercel.json rewrites between the filesystem handle and the generated dynamic-function routes, so a naive catch-all rewrite swallowed /api/clan/:tag and /api/player/:tag into index.html while /api/search (a literal filesystem route) kept reaching its function. The SPA rewrite is now /((?!api/).*) -> /index.html: client routes serve the shell, api paths never match it, and unknown /api paths still 404.
- Dynamic segments reach the function as a tag query param, not in the path: the generated route rewrites /api/clan/:tag to /api/clan/[tag]?tag=:tag. tagFromPath prefers the query param (decoded, with a safe fallback) and keeps the path segment as the fallback for local dev, where the tag really is in the path. A unit test locks both behaviors.
- lineHeight tokens stay as design ratios, but createBaseStyles converts each to pixels (ratio x fontSize) via a lineBox helper in one place. RN Web reads a numeric lineHeight as pixels, so lineHeight: 1.2 compiled to line-height: 1.2px under a 36px display font: the line box collapsed and stacked sibling texts on top of each other (the reported "text overlaps" on the deployed home). Screens that already multiplied (TokenScreen, the hello screen description) were correct; only the base styles were not.
- The hardcoded smoke tag is now our own clan #2JPCYP98L: it exists as long as the project does, it is populated (47 members), and its war log is public (verified live: the warlog route answers 200 against it).
- scripts/platform-sim.mjs (+ platform-sim-inner.ts) reproduces the deployed invocation locally: a plain Node http server that calls the api default exports Node-style and dispatches dynamic routes with the manifest's ?tag= rewrite. verify-tier.sh passes 36/36 through it and 36/36 through the regular dev server, so both call contracts are proven before every push.
