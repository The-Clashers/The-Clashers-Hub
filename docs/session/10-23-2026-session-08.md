## Decisions

- The two `api` folders are both intentional, and now signposted in place.
  `api/` at the repo **root** is Vercel's serverless-function convention —
  the platform auto-detects it only there (the same way `public/` is
  root-level) and deploys each file as a function under `/api/*`; those files
  are two-line adapters over `server/`. `src/api/` is the **browser-side**
  typed client that calls those routes over HTTP (currently `clan.ts`, used
  by the hello screen) — it was never empty. A README in each folder states
  the split, so the layout is discoverable without reading the concept docs.
- `api/player/[tag]/` was an empty, untracked leftover from the tier work
  (the player route needs only `api/player/[tag].ts`); removed.
- Local replay matched production on every route. Two transient
  `502 upstream_unreachable` answers occurred (a 4-second timeout on `/war`,
  a fast failure on search); in both cases the immediate retry succeeded and
  the deployed site answered 200 at the same moment. Failures are never
  cached, so a client retry always gets a fresh attempt — the contract
  behaving as designed, now documented with captured evidence.
- Negative caching verified live for the first time: a `404 not_found` is
  served from cache (`x-cache: HIT`, ~1 ms) within its 30 s window and
  re-validates upstream after the window expires.
- Roster note: the smoke clan currently fields 7 members (level 11); the
  hello-screen comment still says 47. Harmless; left for the next session
  that touches the file.
