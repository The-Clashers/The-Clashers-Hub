## Decisions

- The entry route is the search screen, per the URL map in the feature list. The old placeholder home is gone; its M0 review links (hello, tokens) moved to a quiet footer row so both surfaces stay reachable from `/`.
- Filters apply on submit, not while they are tapped. Every distinct filter combination is a distinct cache key on the tier, so live re-searching on every tap would burn upstream calls the TTL cache cannot absorb. A "changed since the last search" hint makes that visible instead of silent.
- Filters are chip rows, not dropdowns: no extra dependency, they work in the React Native paradigm, and the values are a small closed set anyway (members 10 to 50, level 5 to 20, five war frequencies, sixteen curated locations). Chips keep the 44 px touch target from the design language.
- The location list is bundled in `src/api/locations.ts` with ids verified live through the proxy (GET /locations). The tier only proxies the five read routes, so a locations route would be scope creep for a filter dropdown; growing the list is a one-line append.
- The list pages at 30 items per request. A cold search measures 359 ms round trip against the live proxy and a tier cache hit 5 ms, so AC-01 (2 s cached, 5 s cold) has ample headroom even with the render.
- Cursor pagination runs through TanStack Query's useInfiniteQuery: getNextPageParam reads paging.cursors.after, so the list stops cleanly when the upstream stops handing a cursor. Verified live by scrolling: 30 to 60 clans, then "End of results" once exhausted.
- Fixing the mount: the app root collapsed to content height because `#root` was a plain block, so the FlatList had no bounded scroll container, rendered every item at once, and onEndReached fired itself through 13 pages. One line in index.html (`#root { display: flex; flex-direction: column; }`) gives the whole screen chain a real height; hello and tokens still scroll fine at the page level.
- Client staleTime stays 60 s, mirroring the tier's search TTL, the same two-layer pairing the hello screen uses. A 400 maps to the no-retry branch (retrying the same rejected request cannot fix it); 503 and 502 keep the single default retry.
- Search has no not_found state by design: a search that matches nothing is a 200 with an empty items array, so the client union is one branch shorter than the clan client's, and the empty state (with a clear-filters action when filters are active) is that state.
- Known follow-up, not a defect: the F-01 note "empty name = browse top clans" needs the tier to make name optional; that is a tier change with its own tests, out of this card's scope.
- Dev-log hygiene: older logs carried full PR URLs (against the template) and stale repo host names; both are gone from the tree now.
