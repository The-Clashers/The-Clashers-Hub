## Decisions

- The engine lives in `src/lib/`, not `src/engines/`. STD-09 opens
  `src/engines/` with M2; the donation balance is M1 work, and `lib/` is
  the home for pure helpers that can be unit-tested without rendering
  anything (the roster-sort and clan-role rules are the model). The
  rushed engine (M2) opens `src/engines/` when it lands.
- The engine is a pure function: data in, verdicts out. No React, no
  network, no clock (05 section 2, STD-09). That is what makes the
  target adjustable client-side (SR-12): changing the target is a re-call
  with the same members, no refetch. The roster keeps the members from
  the single clan fetch (SR-09) and re-computes locally.
- The verdict is a discriminated union per member: `good` (at or above
  target), `warn` (below target, above noise floor), `dash` (no data,
  both zero). The chip reads the state, never re-computes. The state is
  pre-computed so the render is a lookup, not a calculation.
- `ratio = given / max(received, 1)`. A saint (given > 0, received = 0)
  is not a divide-by-zero; its ratio is `given`, displayed as "given : 0".
  Both zero is no data: a dash, never a red flag (05 section 2 edge cases).
- Noise floor of 50 on received donations. A member whose received is at
  or below this value is never flagged, no matter how lopsided the ratio:
  a brand-new member who received 3 troops has not had a season to balance
  out, and public-shaming them is both noisy and unkind. The value is
  small enough that any real donor clears it inside a week.
- The deficit formula is `target * received - given`. Positive for flagged
  members, zero or negative for members at or above target. The
  needs-attention sort ranks by deficit descending (worst first), with
  the same tiebreak chain the roster sort uses (clan rank, then name, then
  tag) so flipping in and out of needs-attention never shuffles tied rows.
- The RatioFlag chip uses the semantic tokens (success/warning/muted), not
  the gold accent. Gold is reserved for the things that matter (numbers,
  verdicts, focus); the donation flag is a status indicator, and status
  colors are the semantic set (07 section 2).
- The ratio column is appended only when needs-attention is on, so the
  table's column count is stable within a mode and a toggle does not cause
  a mid-scroll layout shift on the rows already rendered. The column
  width is fixed at 96 px to fit the "1,234 : 5,678" format without
  truncation.
- The target control is a chip row of four presets (0.5, 1:1, 1.5, 2.0),
  not a free-form input. A small closed set keeps the control a chip row,
  matches the filter-row pattern, and avoids keyboard entry on mobile. The
  clan health share ("NN% at target") sits next to the chips so the
  leader sees the clan-level verdict at a glance.
- The needs-attention toggle is a switch-role Pressable, not a checkbox.
  The design language's toggle pattern (07 section 4) is a pill that
  changes color when on; the switch ARIA role maps to the platform
  semantics on web and keeps the keyboard path honest.
