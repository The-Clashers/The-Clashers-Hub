## Decisions

- The dropdown is the control, not a chip row or a second header: the kit
  already owns a keyboard-complete select-style Dropdown (07 section 4),
  the search screen's filter row set the usage pattern, and one press per
  choice fits a phone's touch budget better than a cycle.
- Dropdown semantics deliberately differ from the header cycle: a dropdown
  re-pick of the active column is a no-op (the header cycle would toggle),
  because picking an option that is already shown reads as "this one", not
  as "reverse it". The direction toggle owns reversing, and it renders
  disabled in clan order so the two controls never fight.
- The rules live in `lib/roster-sort.ts` (STD-09), not in the screen: the
  module's own header says it owns "what a press means for the row order",
  and a dropdown selection is a press. The option labels are UI copy and
  stay in the screen file with the bar that renders them.
- The sort bar lives in the Clan screen file beside `RosterSection`, per
  session 20's STD-16 call that a roster-with-sort is clan-detail specific;
  the M3 scouting view still renders rosters without sorting.
- No new card on the board: this closes a review gap on T-M1-4's own
  acceptance, so it ships as a follow-up PR against the same card.
