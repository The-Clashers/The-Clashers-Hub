## Decisions

- Fixed, not sticky, for the nav: a sticky bar is constrained to its
  containing block, and #root is exactly viewport-height (the flex chain
  that bounds the search FlatList), so a sticky bar would let go after one
  screenful of roster. Fixed + an in-flow spacer of the same constants
  survives both scroll models the app uses.
- The nav bar and the tab strip share the recorded compact-exception entry
  (07 section 6): the rows run thin by the owner's call while every
  pressable inside keeps the 44 px floor and the gold focus ring.
- Needs Attention is a fresh view per visit rather than a lifted target:
  the ratio drafts cannot be re-derived from the float target without
  lying, so the target and the drafts reset together to 1:1 when the tab
  re-mounts. The toggle-era mounted-drafts rule scoped itself out with the
  toggle.
- The attention table has no sort controls: the row order is the engine's
  judgment, and a control that cannot change the order would be a control
  that lies.
- `?name=` is consumed once and stripped: the param is an entry hint from
  the nav lookup, not app state, so a reload or back-navigation starts
  idle instead of replaying a search.
- The contributors list is fetched client-side from api.github.com: the
  repo is public, the call carries no secret, and the tier only proxies
  the game API. Rate limiting (60/hour per IP) is the real failure mode,
  so it gets its own error branch and copy instead of a generic retry.
- The rank parse (trailing integer on the tier name) lives in
  lib/league-rank.ts with tests, ready to retire the day the API splits
  the rank into its own field.
