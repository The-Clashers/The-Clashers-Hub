## Decisions

- The header reads leagueTier, not the classic league object: the roster's
  rank column already reads the new themed ladder ("the way the game shows
  it"), and the player header must never disagree with the roster about
  which ladder it shows. The classic league stays in the parse as the
  fallback for payloads that carry no tier; a real Unranked tier renders
  like any other tier, the same call the roster makes.
- Breadcrumbs read Home > Players > <name>, not the clan path: the trail is
  a location line, not a history line, and /player/:tag lives under the
  Players surface in the URL map. Golden path A's way back to the roster is
  the browser's back button; the clan the player belongs to reads in the
  identity card's meta line as plain text, the same quiet treatment the
  clan card gives its own meta.
- The analysis sections render as EmptyState notices, not empty section
  frames: the clan screen's War and Log tabs set the house pattern for
  "this surface lands later" (titled, explained, pointing at the card that
  fills it), and the shell repeats it so the page reads end to end today.
- The identity card's stat grid wraps two per row inside the identity
  column even on desktop viewports: the column the two-column layout gives
  the card is narrower than the tablet breakpoint the clan card's four-up
  rule keys on, and a league name like "Electro League 31" needs the cell
  width. When the card runs full width (stacked, tablet and up) it takes
  the clan card's four-up form, so the two detail cards read as one family
  wherever they share a width.
- The clanless player renders the quiet dash in the clan role cell and the
  tag-only meta line, not a designed empty state: the screen's data is the
  player, and a missing clan is a within-success degradation the way a
  missing badge is on the clan card.
