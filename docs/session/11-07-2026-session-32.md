## Decisions

- The icons pass came forward out of T-M2-5/T-M2-6 on the owner's call
  ("put it forward"), scoped to what the hero panel renders today:
  heroes and hero equipment. The map's kind union ('hero' |
  'equipment') is shaped so the progression grid extends it with
  troops, spells, pets, and siege machines without the lookup or the
  component changing shape.
- Name honesty over name coverage: only names recorded off real
  payloads are treated as verified. The rest are derived from the
  Fankit file names (underscores to spaces, joined CamelCase split)
  and marked as such, because the live chain was unreachable (the COC
  key is IP-bound to the pre-rebuild sandbox, see session 31). A
  derived spelling that does not match the API never resolves and the
  placeholder shows, which is the designed fallback, so the guess can
  cost a quieter row but never a wrong picture. T-M2-6 trues the
  spellings against the live payload.
- UnitIcon's accessibility treatment is decorative-by-default: an RN
  Image without an accessibilityLabel renders with an empty alt, the
  web's explicit decorative marker, and every surface rendering a
  UnitIcon already labels its row with the name. An aria-hidden prop
  was tried and removed as a no-op RNW swallows; the comment records
  the real mechanism instead of a prop that pretends.
- The equipment row keeps the hero row's line shape one scale down
  (icon + baseline text row) rather than mixing an image into a
  baseline-aligned row: one mental model, and the icon centers level
  with its text whatever the digits do.
- Only the mapped icons ship: the build emits the 49 assets the map
  imports, tree-shaking the other 102 bundled files until the grid
  maps them. The bundle scan went from 2 to 50 files, all clean.
