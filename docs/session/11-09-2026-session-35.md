## Decisions

- The tier mirrors the three-character floor rather than letting the
  rejection travel upstream: the game API's own rejection costs a round
  trip and surfaces as a reason code; ours costs ~1 ms and carries a
  sentence. The floor lives in the request-contract module
  (`SEARCH_NAME_MIN_CHARS`) so the tier's validation message, the two
  input hints, and the test that pins the number all read one constant's
  documentation.
- Client-side filters stay in the submitted-filters object (and therefore
  the query key) rather than a separate state: the screen's draft, the
  dirty check, the chips, and the re-submit patches all stay one shape.
  The cost is that changing one re-keys the query (TanStack refetches even
  though the request is identical); the tier's 60 s TTL absorbs that, and
  apply-on-submit means the only rapid paths are the explicit ones (press
  Search, press a chip's ×).
- Removing an applied chip is an immediate submit. Every other filter
  change waits for Search (each distinct server-side combination is a
  distinct upstream call), but a chip is the applied state itself —
  removing it is not a draft edit, it is a re-search.
- "Clan size" is one bracket control, not two numeric fields: minimum and
  maximum members are how the tier speaks, but "up to 10 / 10–30 / full"
  is how people search. The bracket maps to the pair, and every branch
  spells both bounds so a selection never leaves a stale half behind.
- The join gates read as caps ("Up to 2,000 trophies", "Town Hall 14
  max") and an absent gate passes every cap: "no requirement" is the
  easiest clan to join, so it is always an honest match, and the "None"
  option (threshold 0) selects exactly those clans.
- isFamilyFriendly renders as a tag, not a StatChip and not a filter: the
  owner asked for a tag, a property of the clan is not a number it earned,
  and only true renders — most clans are false and the row should not
  carry a permanent "no".
- The label and chat-language tables are bundled curated lists (the same
  call the location filter made) rather than new tier routes: five label
  ids verified from the live captures, English's language code verified
  live, the rest of the language codes marked to-true with the failure
  mode visible (a wrong code reads "0 shown of N loaded", never silently
  no-ops, and the fix is a one-line table edit).
- The chat-language filter matches on `languageCode`, not the numeric id:
  the code is what the payload reports and what a one-line edit can true
  against a live capture.
