## Decisions

- Supabase, and not a re-litigated vendor: the storage ladder already named
  it (06 section 5), and the free tier covers the need with room (the volume
  math in 10 section 9: ~18k member rows a year for one clan, a few MB
  against the 500 MB cap). The alternatives each break a v1 rule: Firebase
  has no SQL story for roster diffs, PocketBase is self-hosting (the ops
  class the no-database decision existed to avoid), Neon-class Postgres is a
  database only.
- The key boundary becomes three keys with three rules instead of one key
  with one: the CoC key and the Supabase service key stay server-only under
  the existing discipline, and the anon key is named public-by-design with
  an explicit scan allowlist entry, because pretending a public key is a
  secret would weaken NFR-04's meaning rather than honor it.
- Discord OAuth is the front auth door, email and password the secondary:
  the free tier's built-in email provider sends 2 emails per hour
  project-wide, so a demo-room full of password sign-ups would exhaust it in
  minutes, while Discord asks for no email at all.
- Binding verification runs through the tier, never the browser: the
  upstream verifytoken call needs the CoC key, so the flow is tag, preview
  against the existing player route, paste the in-game token, then
  POST /api/link/verify. One binding per player tag (a village belongs to
  one account), minis as extra rows, unbind as a hard delete with the tag's
  snapshot history surviving.
- Home analytics split in two phases because the API already returns
  history for wars and capital raids but nothing time-based for rosters:
  phase A is five live widgets off existing routes (plus one new capital
  route), phase B is the five snapshot widgets that need the sync. The hero
  lookup stays above the fold; analytics render below it.
- The players screen keeps the API's rule (no player name search upstream)
  and fixes the emptiness around it: recent searches, your bound accounts,
  saved players, and the bound clan's roster as a browser-side name-searched
  directory, which is honest because it searches a roster we already hold.
- Snapshots run as a daily Vercel cron (the Hobby cap is two jobs at once a
  day, which matches the cadence) hitting a shared-secret /api/sync route;
  a Supabase scheduled function was noted and declined to keep every key in
  one place. The watched set is clans with at least one binding, capped at
  five, with an 18-month prune.
- This PR changes no behavior, so the five concept amendments land as
  conditional pointers now and the real edits ride with the activation PR
  (T-M5-1/T-M5-7), keeping the definition-of-done rule 5 intact both ways.
