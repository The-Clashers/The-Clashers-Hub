## Goal

The owner's rework of the freshly merged search filters: drop the minimum
clan points control, turn the clan level and Town Hall requirement filters
into number boxes (the Town Hall box capped at the highest hall the game
API provides), replace the trophies requirement with the league requirement
the rank rework actually returns, fix the scrollbars the dropdowns were
painting on every list, and redesign the search container and filter layout
around it.

## Decisions

- The league filter reads the ladder position off the tier id, never the
  name: the id is the API's ordinal (105000000 + tier) and a name is a
  label we bundle. A tier id outside the known ladder (content newer than
  the bundle) is a requirement we cannot rank, so it drops out while a cap
  is in force — not provably at-or-below any cap — and passes when no cap
  is set. The failure mode is visible and honest, the same posture the
  chat-language table takes.
- "None" keeps the old trophy filter's gate-less semantics: an absent
  `requiredLeagueTier` passes every cap (no requirement is the easiest
  clan to join), and threshold 0 selects exactly those clans.
- The Town Hall cap comes from `lib/town-hall-caps.ts` rather than a new
  tier route or a leaderboard probe: that module is the project's own
  source of truth for what the game provides (reference-data version
  November 2026, TH18, cross-checked against live payloads in session 31),
  and "up to the highest possible TH the API provides" is exactly the
  number it already owns. A docs-sized PR bumps it when the game ships a
  new hall.
- Minimum clan points is gone from the UI but the tier keeps accepting the
  param: the tier mirrors what upstream can filter (documented in 04
  section 5, covered by its own tests and verify-tier checks), and an
  API-direct caller may still want it. The client and the screen simply
  stopped offering it.
- The clan detail card swaps its "Trophies req" cell for "League req"
  (tier name, quiet "None" when the clan asks for nothing): the rework
  changed the requirement data itself, so showing the legacy number would
  have rendered a permanent zero. The clan client drops the
  `requiredTrophies` parse entirely — covering only the fields the screens
  read is the folder's stated rule.
- All filters now live behind the one disclosure rather than keeping four
  primary controls always visible: the name search is the golden path, a
  360px phone keeps the whole container above the fold, and the applied
  count plus the chip row keep the state glanceable while collapsed.
