## Decisions

- The hint reads the response's own age and stays static; it does not tick.
  "Cached" is a claim about where that specific answer came from (the
  tier's cache), and aging the number on screen would eventually turn a
  fresh upstream answer into "Cached, Ns ago" while it is the client's
  copy that is aging, not the tier's. The response's testimony stays as
  answered; the cooldown is the number that must live-tick, because it
  counts down to an action's availability.
- The age > 0 test is the cached signal, not the `x-cache` header: the
  header would ask the api clients to start reading response headers they
  never touch, while the age field is already parsed, already typed, and
  already flows through the query data. A HIT served within the same
  second as its store reads "Fetched just now", which is true to within a
  second.
- Placement follows each screen's existing freshness line rather than one
  forced position: the meta row above the search results, the footer under
  the clan and player detail. The component is identical across the three,
  so the control reads as one family while the screens keep the layout
  decisions they already made (the same call the lookup panels' shared
  shape made).
- The cooldown lives in component state, not persisted: it is "pure
  courtesy, not correctness" by the concept's own words, the tier's cache
  is the real guard, and a control that survives navigation would need a
  store for a rule nobody asked to survive. Navigating away and back
  re-arms a fresh button; the upstream was never at risk either way.
- The live-data screens today are the clans search, the clan detail, and
  the player detail: the routes the tier serves that have screens. The
  war and warlog routes get their screens in M3, and the control is the
  shared kit piece they will mount then; the contributors page reads the
  GitHub API, not the game tier, so FR-18's TTL framing never applied to
  it.
- The button label carries its own state ("Refresh", "Refreshing…",
  "Refresh (43s)"): a bare disabled button reads broken, and the countdown
  number is the affordance that teaches the cooldown exists. The PillButton
  doubles the label as the accessibility label, so the screen-reader
  announcement tracks the countdown for free.
