## Decisions

- The war fetch now runs while the War or Needs Attention tab is open (both read the same TanStack Query entry behind the tier's 120s cache), and its retry policy grew to mirror the clan fetch: busy answers pace through lib/busy-retry, not_found and bad_request stop early since the clan itself already loaded.
- Per-member destruction is the average across the attacks the member actually used, and a zero-attack member reads the dash. SR-19's "never averaged in as zeros" rule is applied to the raw view now, ahead of T-M3-7's impact engine.
- The verdict chip (gold Leading during battle day, green Winner once ended) resolves through lib/war-standings' leadingSide, the game's own stars-then-destruction order, so the view can never disagree with the game's result screen. An even war or a preparation day wears no chip.
- Both rosters render, the viewed clan first and the opponent under its own badge heading, because a war organizer reads the enemy's attacks too; every row taps through to player detail like the roster rows.
- The parse sorts members by map position (unknown positions fall to the end in payload order), the order the game's own war screen keeps; no sort controls on the table for the same reason the attention table has none.
- Browser verification caught a real mobile bug before it shipped: the standings cards carried flexBasis 0 unconditionally, which collapsed their height in the stacked sub-768px layout and poured both cards' content over each other. The row-sharing flex now applies only in the two-up layout, in the loading skeleton too.
- Ended-state rendering was verified against a mocked upstream payload derived from live data (no clan sat in the brief ended window during the session); battle day (40v40), preparation day (20v20), and no war were verified against live upstreams.

## Blockers

- The COC_API_TOKEN in the local .env is rejected upstream (403 accessDenied "Invalid authorization" through the proxy and against the official API), while the production deploy answers live data fine, so local verification ran the new bundle through vite preview with /api proxied at the deployed tier. Local dev needs a fresh key (allowlisting the proxy's current IP).
- The vite dev server (npm run dev) fails to serve react-native-svg's web build in this environment: the PEG-generated transform.js is CommonJS but is served raw as an ES module ("does not provide an export named 'parse'"), leaving a blank page. vite preview on the built bundle works (rollup handles the interop) and was used instead. The exclude alias landed only yesterday (4c8acf9), so this is worth a look before the next dev-server-dependent session.
