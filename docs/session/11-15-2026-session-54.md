## Decisions

- Roster size is a fact, not a verdict: a 30-member clan is not a worse 50-member clan, so the engine's metric kinds grew a 'fact' (both values primary ink, the unsigned gap in quiet ink, no side colors) instead of forcing Members into higher-better where the coloring would lie. Every other clan metric in 05 section 4's list reads higher-better.
- A row compares at the precision it displays. The first live render caught two win rates a fraction apart both reading 44% while the raw delta declared a leader and a "+0" margin; the share rows now quantize to whole percents and the decimal rows to one place before the verdict, with the delta formatted through the same precision, so equal displays read "Even". The player compare's own rows compare values that are already integers or engine-rounded, so it needed no change.
- A war log that fails to load is its own state, never the private log's copy: the private reading is a success shape (dashes plus the sample note), while a failed fetch keeps the answered side's rates on screen, dashes only the failed side, and swaps the note for a retry panel. The first implementation nulled both sides on one failure, which contradicted its own panel naming only the failed tag; the browser pass caught it against a killed upstream.
- The sample-size note rides on the group (the CompareGroup grew an optional note the player compare does not set), naming each side's window and league count, and naming a private log as the dash's reason, so nobody mistakes the dash for a failure or over-reads a 2-war window.
- The picker resolves names because the game API searches clans by name (players it does not, which is why player mode stays tag-only). A comparison needs two exact clans, so a submitted name opens the picker instead of navigating to a broken URL, and a completed pair auto-submits the original Compare press.
- The identity cards repeat two compared metrics (Members, Average TH) as context cells plus the war log's visibility — the player compare's own precedent (TH and XP ride both its card and its Account rows), and the War log cell means the private dashes below never surprise.
- The mock's `#MOCKCLAN` warlog went public to match what the clan fixture's `isWarLogPublic: true` always claimed (the route answered 403, so the detail card and the Log tab told two stories locally), and the warlog fixture was rebuilt in the live payload's shape after discovering every entry dropped at the parse (no clan side object, so `toWarlogEntry` filtered them all).
