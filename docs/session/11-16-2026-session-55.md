## Decisions

- The launch action sits where the VS badge sat, not beside it: one compact gold pill between the two boxes replaces both the badge and the old full-width launch button, so the card carries a single compare affordance and reads shorter. The pill keeps the control-height token rather than shrinking to the old 32 px badge size, which is what lands it level with the input boxes (labels above, helpers below, so the row's midpoint is the inputs' band) and keeps the touch floor.
- The result screens keep their VS face-off bands: the badge between the identity cards there is a verdict display, not a dead control, and the owner's screenshots named the landing pages alone. The landing's VS was decorative seating for an action that lived elsewhere; the face-off VS is the only "versus" the comparison itself has.
- Clan mode loses the inline search affordance for the identical box chrome because the two modes' cards were the inconsistency the owner named; the name flow it opened stays fully reachable (type a name, press Compare, the picker opens seeded with it, taught by the helper copy that already said so), and the popup's focus return now lands on the Compare button that opened it.
- The stacked (below tablet) seat centers the pill through the seat's own `justifyContent`, because the pill's base `alignSelf: 'flex-start'` (correct in the kit's other seats) wins against a column's `alignItems` and pinned the first try to the left edge; the browser pass caught it at 390 px.
- The footer pin lives in the app shell, not the Footer component: the percentage `min-height` chain never resolved (body's height is auto, so `#root`'s percentage had nothing to resolve against, leaving a dead strip below the footer on every short page), and react-native-web drops `marginTop: 'auto'` outright, so the working mechanism is `#root` as a viewport-height flex column plus the screens' existing flex-growing roots, one fix for every route at once.
- The picker's Escape bug was reproduced on main before touching it: the same keydown-swallowing sat under the old magnifier opener too, but nothing in that flow made the miss obvious (the magnifier kept focus outside the input until the popup took it, and session 54's pass checked Escape from outside). The fix is the capture-phase registration, one flag on the existing listener, not a redesign: capture runs before the target's handlers, so Escape closes from wherever focus sits and still returns focus to the opener.
