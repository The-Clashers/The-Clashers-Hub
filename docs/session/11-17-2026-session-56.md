## Decisions

- The clans screen records its own lookups rather than leaning on the detail screen's recording: the tag path leaves for the detail immediately, so without recording at submit the strip's evidence for that lookup exists only if the detail fetch succeeds (a failed fetch, a busy retry, or a back-button bail would leave no trace). The detail's later recording with the name label upgrades the entry; the submit-time recording guarantees it exists.
- A name search records as a clan-kind lookup with the name as the query, matching LookupSearch's clan mode (the nav bar and home hero already record names that way), so all three clan entry points produce the same chip shape and the chip's round trip is the same everywhere: back to `/clans` with the name pre-filled.
- A chip's name search submits with the current filter draft, not the submitted filters: the chip means "run that lookup again," and the filters row is the visible state the user can still edit, so the re-run agrees with what the screen shows. (The first draft of this handler spread a memo that carried the old `name` key after the new one and would have re-run the previous search; caught in self-review before commit.)
- The strip re-reads on `storage` and `focus` rather than polling: `storage` is the browser's own cross-tab notification (it does not fire in the recording tab, which is fine, because the recording tab re-renders through its own state), and `focus` covers the same-tab nav-bar case where no storage event ever fires. Both listeners filter to the recent-searches key where the event carries one, and clear on unmount.
- No component test for the strip: the project's test setup is node-environment, pure-logic only (vitest.config.ts, no testing-library, no component test exists), so the strip's refresh behavior stays covered by the helper's tests plus the typecheck; adding a DOM test harness for one listener would be scope creep against the convention.
- The compare screens still do not record (session 53's call stands): the lookup flows that own recording keep it, the compare is its own feature with its own inputs.
