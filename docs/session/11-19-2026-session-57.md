## Decisions

- **Layered Edge ISR + Supabase SWR over static-only caching**: Replacing `no-store` with per-route `Cache-Control: public, max-age=0, s-maxage=<TTL>, stale-while-revalidate=<SWR>` on public GET routes lets Vercel Edge absorb bursts while Supabase Postgres serves as the shared L3 SWR + `stale-if-error` store. Injecting `"fetchedAt"` epoch ms keeps `RefreshControl` age indicators honest across Edge hits.
- **303.5 MB operational cap inside Supabase's 500 MB free tier**: Stripping unused upstream JSON fields before persisting (`~4.5 KB` player, `~8.5 KB` clan), storing only 250-byte scalar summaries for bound progression snapshots (never raw 22 KB JSON histories), enforcing 1:1 CoC binding (`user_id` PK + `player_tag` unique) and per-user row caps (25 bookmarks, 10 compare pairs, 90 snapshots/tag), and running a 3-tier watermark guard (`<350 MB` Green / `350-425 MB` Yellow / `>425 MB` Red) keeps worst-case DB size well below 500 MB.
- **Official CoC `verifytoken` 1:1 binding without token storage**: Each user account binds one Clash of Clans player account via `POST /players/{playerTag}/verifytoken` with their rolling in-game API token (`Settings -> More Settings -> API Token`) and immediately discards the token on completion.
- **Supabase Auth login implemented (`/auth`)**: Users sign in or create accounts on `/auth` with mandatory `/terms` data consent, unlocking verified 1:1 CoC binding, progression history, cloud watchlists, and persistent preferences (`/profile`, `/settings`, `/terms`).
