## Decisions

- The default was first kept on `Latest` (reading the ask literally: the
  landing state stays what the screen always carried), then the owner's
  same-day follow-up flipped it to the player's own Town Hall limits
  explicitly, so the first reading a player lands on is the
  maxed-for-my-Town-Hall one and `Max` is the option. The flip changes
  only view-local state on one screen: the engines, the adapters, and the
  compare screens keep their explicit frames.
- The captions became frame-aware rather than keeping the old fixed line,
  because the old caption was wrong in the default frame: "DEFICIT VS TH
  CEILING" and "measured against the TH14 ceiling" while the engine measured
  the API's global maxima. The latest frame now says what it reads ("DEFICIT
  VS MAX", the follow-up's name), the Town Hall frame owns the ceiling
  phrasing the old caption borrowed.
- The toggle first sat under the breadcrumb above both columns, then the
  owner's follow-up moved it into the refresh card: the two screen-level
  controls read as one panel (the lens and the freshness of the same
  reading), and it stays screen-level state rather than a control inside
  any one analysis card, because the reading it changes lives in both
  columns; seating it inside the rushed card (or each card) would read as
  that card's own and leave its siblings looking unresponsive.
- The Town Hall frame reads the cap tables alone, with no global-max
  fallback for a unit the tables have not met: "done for this hall" has
  exactly one honest source, and borrowing the TH18 maximum into a TH14
  verdict would mix two yardsticks inside one percentage. The existing
  skip-and-footnote path (SR-14's shape) is the honest answer for not-met
  content, the same posture the engine already kept for null maxLevel.
- Builder-base rows answer to the Builder Hall, read from a tolerantly
  parsed `builderHallLevel`: a payload without the field (0) keeps those
  rows on the global maximum rather than fabricating BH1 caps (every builder
  unit reads 0 there). The official payload shape carries the field (the
  RoyaleAPI mirror documents it on the player object); the parse degrades
  honestly if a payload ever arrives without it.
- The compare screens stay on the global frame on purpose: two players face
  off against one yardstick, and a per-side hall frame would compare two
  different denominators. The toggle is view-local state on the player
  screen, not a URL param (it is a lens on the data, not a shareable fact
  about the player).
